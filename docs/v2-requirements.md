# V2 요구사항 — 설계사·대리점용 MCP 서비스

작성일: 2026-10-28

상태: 서비스 요구사항 초안. 독립 인프라 기반만 구현됐으며 업무 기능·운영 배포 완료를 의미하지 않습니다.

기준: 현재 코드 `6736a02`, [전환 설계 및 구현 계획](v2-implementation-plan.md)

**후속 사용자 결정:** V1을 수정하지 않고 V2 서버·DB·배포 파이프라인을 별도로 구축한다. DB는 Neon 별도 프로젝트를 사용한다. 현재 인프라 구현과 운영 절차는 [V2 배포 가이드](v2-deployment.md)를 따른다.

## 1. 제품 정의와 합의된 경계

> 보험설계사·대리점이 자신이 사용하는 MCP 지원 AI에 연결하여, 접근 권한이 있는 고객의 보험 정보를 관리하고 예상 보험금을 산출하는 서비스.

- 직접 이용자와 도입 주체는 설계사·대리점이다. 고객은 보험 정보의 대상이며 MCP 가입·연결이 필수인 사용자가 아니다.
- 고객 상담과 업무 처리는 설계사 측 AI가 담당한다. 이 서비스는 MCP Tools·Resources·선택적 Prompts만 제공한다.
- 이미지/PDF 판독과 대화는 외부 AI, 약관 조건 대조와 금액 계산은 서버의 결정론적 엔진이 담당한다.
- 정보 제공용 예상치만 반환한다. 실제 지급 여부·금액은 보험사 심사에 따라 달라진다.
- 원격 Streamable HTTP를 업무용 기본 연결로 한다. 업무 REST API, OpenAPI, 웹 브리지, 자체 AI는 범위 밖이다.

| 설계사 측 AI의 역할 | MCP 서비스의 역할 |
|---|---|
| 고객 상담·업무 순서·자료 수집 | 호출자 인증, 업무 공간·고객 접근 권한 검증 |
| 문서 판독·구조화·내용 확인 | 고객별 구조화 보험·특약 데이터 관리 |
| 고객에게 부족한 정보 질문 | 부족한 필드·근거·서류를 기계 판독 가능한 형태로 반환 |
| 결과 설명·안내서 제작·고객 전달 | 예상액·판정·근거·검증 상태·계산 제한 반환 |
| 자체 CRM·상담 이력·후속 업무 | 최소한의 보안 감사·사용량·운영 관리 |

MCP Prompt는 도구 사용 예시일 뿐이다. 특정 상담 스크립트나 Prompt 실행을 정상 호출의 전제 조건으로 요구하지 않는다.

## 2. 확인된 현재 상태

다음은 코드 확인 사실이며, 이 문서 작업에서 운영 서버를 재검증한 결과는 아니다.

| 항목 | 현재 구현 | V2에 필요한 변화 |
|---|---|---|
| 인증 | 사용자별 키가 `users.user_id`에 귀속 | 설계사 신원과 보험 가입 고객 분리 |
| 데이터 소유 | 보험이 `user_id`에 연결됨 | 업무 공간·고객·명시적 접근 권한 도입 |
| 계약 식별 | `(user_id, company, product_name)`로 업서트 | 동일 상품 복수 계약을 구분하는 비민감 식별자 필요 |
| 평가 | 진료 입력을 저장하지 않고 결과 반환 | 비저장 유지, 구조화된 보완사항·버전 정보 추가 |
| MCP | Tools 11개, Resources 3종, Prompt 1개 | 다고객 도구 계약 추가, 개인용 계약 보존 |
| stdio | HTTP 키 인증이 적용되지 않음 | 업무용 다중 테넌트 데이터에 무인증 접근 금지 |

근거 파일: `src/claim_service/api/auth.py`, `service.py`, `db/tables.py`, `db/repository.py`, `mcp/server.py`, `domain/models.py`, `domain/evaluator.py`.

**검증 상태의 주의점:** 현재 `MAPPED` 특약은 정책·특약의 증권 출처 조건을 충족하고 특약의 `rule_config_override`가 있으면, 미검증 표준 규칙 대신 override를 검증된 복사본으로 만들어 평가할 수 있다. `CUSTOM`은 현재 계산 보류한다. 따라서 “모든 계산 조건이 서버에서 약관 원문 검증됐다”는 의미로 현재 결과를 해석하지 않는다. V2는 문서 출처 진술과 지급 조건의 실제 검증을 별도로 다뤄야 한다.

사용자가 실제 데이터 입력·MCP 연동·산출 완료를 확인했다. 이는 유효한 기능 검증이지만, 모든 상품의 약관 정확성·다고객 격리·모든 AI 클라이언트 호환성 검증을 뜻하지 않는다.

## 3. 용어와 접근 모델 — 제안

| 개념 | 정의 |
|---|---|
| `actor` | 인증된 설계사 개인. AI 클라이언트는 이 사용자의 자격으로 호출한다. |
| `workspace` | 개인 설계사 또는 대리점의 데이터 격리 경계 |
| `membership` | actor의 업무 공간 소속·상태·관리 역할 |
| `client` | 업무 공간 내 보험 가입 고객. 서비스가 불투명한 `client_id`를 발급한다. |
| `client_access` | 특정 membership에 부여된 고객별 읽기·쓰기·평가 권한 |
| `processing_authority` | 고객 자료 처리 권한의 목적·범위·유효기간·철회 상태 기록 |

- 개인 설계사도 1인 업무 공간을 사용한다. 대리점은 같은 구조에 여러 membership을 둔다.
- 같은 대리점 소속이라는 이유만으로 고객 전체를 조회하지 못한다. 관리 역할과 고객 자료 접근 권한은 별개다.
- 업무 키는 actor와 한 workspace에 바인딩한다. 사람 간 키 공유를 허용하지 않는다.
- actor ID·역할은 인증 정보에서 결정한다. AI가 도구 인자로 보낸 값을 신원으로 신뢰하지 않는다.
- 모든 고객 대상 호출은 `client_id`를 명시한다. 전역 또는 대화 세션의 ‘현재 고객’에 의존하지 않는다.
- `policy_id`, `rider_id`, 검증 근거 ID도 반드시 인증된 workspace와 지정 client의 소유 관계를 확인한다.
- 다른 업무 공간에서 동일한 고객을 등록해도 자동 연결·검색·병합하지 않는다.
- 별명은 표시용이지 본인 확인 수단이 아니다. 서비스는 이름·주민등록번호로 고객을 전역 검색하지 않는다.

## 4. 초기 파일럿 범위 — P0 제안

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| R01 | 설계사 인증과 업무 공간 격리 | 위조·폐기·만료 키와 비활성 membership은 거부; 다른 공간 자료 노출 없음 |
| R02 | 고객 등록·접근 범위 | 불투명 ID와 최소 별명으로 등록; 목록·검색·개별 조회가 동일 권한 필터 사용 |
| R03 | 자료 처리 권한 | 최소 고객 레코드 생성 외 보험 저장·열람·평가에는 유효한 목적별 처리 권한 필요 |
| R04 | 보험·특약 관리 | 고객·계약별 분리; 같은 보험사·상품의 계약 2건이 덮어써지지 않음 |
| R05 | 예상 보험금 평가 | 동일한 확인 입력·규칙·보험 버전에서 동일한 계산 결과; 필수 정보 부족 시 보류 |
| R06 | 결과 계약 | 판정·보류 코드·누락 필드·근거·버전을 구조화; 보류를 보장 없음으로 표시하지 않음 |
| R07 | 재시도·동시 수정 | 중복 등록 방지; 동일 멱등 키의 다른 입력 거부; 오래된 버전 수정은 충돌 |
| R08 | 최소 운영 기능 | 개별 키 발급·폐기, 권한 철회, 내용 없는 감사 기록, 분산 호출 제한 제공 |
| R09 | 클라이언트 연결 검증 | 실제 대상 AI에서 원격 연결·도구 열거·등록·산출·오류 처리를 직접 확인 |
| R10 | 기존 이용 보호 | 기존 개인용 키·도구의 의미 유지; V2 고객 권한으로 자동 승격하지 않음 |
| R11 | 자료 수명 관리 | 보관 기한 설정, 처리 중단·철회·삭제 절차 및 백업 삭제 반영 기한 검증 |

초기 운영자는 별도 CLI로 업무 공간·소속·고객 권한·처리 권한 기록·키를 관리한다. 고객 자료 처리 권한은 설계사 측의 증빙 참조와 책임 확인을 기록하되, 기록만으로 적법성이나 본인 동의가 입증됐다고 주장하지 않는다. 초기에는 일반 AI 도구에 타인의 권한 부여·역할 승격 기능을 노출하지 않는다.

## 5. MCP 계약 — 설계 제안, 아직 호출 불가

V2는 별도 서비스 URL의 `/mcp`를 사용한다. V1 URL의 `/mcp` 및 개인용 도구는 그대로 둔다. 아래 업무 도구는 아직 설계 제안이며, 현재 새 서버는 인프라 확인용 `get_workspace_context`만 제공한다.

| 도구 | 주요 입력 | 주요 출력 |
|---|---|---|
| `get_workspace_context` | 없음 | 인증된 actor·workspace·권한·스키마 버전; 비밀 제외 |
| `create_client` | 비민감 별명, `idempotency_key` | `client_id`, 버전; 최소 레코드 생성 |
| `list_clients` | 선택 별명 검색, `cursor`, `limit` | 권한 있는 최소 목록, `next_cursor` |
| `get_client_profile` | `client_id` | 등록·보완 상태, 건수, 필요한 확인 정보 |
| `register_client_policy` | `client_id`, 계약 참조, 구조화 보험, 멱등 키, 수정 시 버전 | 생성/수정 구분, 계약 ID·버전, 미확인 특약 |
| `list_client_policies` | `client_id`, `cursor`, `limit` | 권한 있는 보험·특약과 출처·검증 상태 |
| `resolve_client_rider` | `client_id`, `rider_id`, 매핑·금액, 버전·멱등 키 | 수정된 특약·버전·미확인 조건 |
| `delete_client_policy` | `client_id`, `policy_id`, 버전·멱등 키 | 해당 계약의 삭제 처리 결과 |
| `evaluate_client_claim` | `client_id`, 구조화 진료 입력 | 아래 평가 결과; 진료 입력 비저장 |

- 계약 참조는 고객별 비민감 임의 식별자이며 증권번호를 요구하지 않는다. 계약 불명확 시 자동 덮어쓰기 대신 확인을 요청한다.
- 보험 등록 응답과 고객 프로필은 `missing_fields`, `pending_items` 같은 기계 판독 필드를 제공한다. AI용 자연어 질문은 선택적 보조 정보다.
- 표준 규칙·서류 안내 Resources를 유지한다. 고객별 Resource를 추가할 때도 도구와 같은 권한 검사를 적용한다.
- 입력 길이·페이지 크기·특약 수·중첩 깊이에 상한을 두고, 알 수 없는 필드와 지원하지 않는 조건을 조용히 무시하지 않는다.
- 쓰기·삭제 도구는 MCP의 해당 버전이 지원하는 읽기 전용/파괴적 동작 annotations를 명시한다. annotations나 AI의 확인 문구는 서버 권한 검사를 대체하지 않는다.

### 평가 응답의 필수 의미

| 필드 | 요구 의미 |
|---|---|
| `schema_version`, `request_id` | 계약 버전 및 내용 없는 추적 ID |
| `client_id`, `policy_versions` | 평가 대상과 실제 사용한 보험 스냅샷 버전 |
| `engine_version`, `rule_versions` | 엔진·적용 조건을 식별하는 불변 버전 |
| `evaluation_status` | `COMPLETE` / `PARTIAL` / `NOT_EVALUATED`; 지급 승인 상태가 아님 |
| `benefits[]` | 계약·특약 ID, `ELIGIBLE`/`EXCLUDED`/`NOT_EVALUATED`, 금액, 근거 |
| `reason_code`, `missing_fields` | 자유문 해석 없이 추가 작업을 결정할 수 있는 코드·필드 경로 |
| `evidence`, `verification_status` | 사용한 문서 참조·조건 버전·검증 주체/상태; 원문 포함 금지 |
| `total_estimated_payout` | 계산된 항목만의 합계. 보류가 있으면 전체 예상액으로 단정하지 않음 |
| `required_documents`, `limitations`, `disclaimer` | 필요 서류, 계산 범위·제약, 정보 제공용 고지 |

- `NOT_EVALUATED`의 `estimated_amount`는 `null`, 검증된 제외는 `0`으로 제안한다. V1의 보류 0원과 구분한다.
- 담보 누락·출처 미확인·미지원 조건도 보류 항목으로 드러낸다. 평가 대상이 없으면 성공한 0원 평가처럼 반환하지 않는다.
- 부분 계산 가능 여부와 보험금 합산 제약을 명시한다. 특히 복수 실손 계약은 단순 합산하지 않으며 비례보상 미지원 시 해당 계산을 보류한다.
- 비용 등 미입력 값과 명시적인 0원을 구분한다. 현재 기본값 0을 V2 판독 확정값으로 간주하지 않는다.
- 결과에 입력 전체를 복사하지 않는다. 응답 근거에도 필요한 정보만 최소로 반환한다.

### 오류 계약

인증 오류는 transport 계층, 도구 업무 오류는 MCP tool error의 구조화된 계약으로 구분한다. 구체적인 SDK 표현은 상호운용 테스트로 고정한다.

`UNAUTHENTICATED`, `ACCESS_DENIED`, `CLIENT_NOT_FOUND`, `PROCESSING_AUTHORITY_REQUIRED`, `VALIDATION_ERROR`, `VERSION_CONFLICT`, `IDEMPOTENCY_CONFLICT`, `RATE_LIMITED`, `TEMPORARILY_UNAVAILABLE`을 최소 코드 후보로 한다. 오류에는 `request_id`, `retryable`과 필요 시 `retry_after_seconds`를 제공한다.

존재하지 않는 고객과 권한 없는 고객은 외부에서 같은 not-found 계약으로 처리한다. 오류·목록 건수·커서·근거 참조를 통해 다른 고객 존재를 노출하지 않는다. 입력 오류와 계산 보류를 구분하며 서버 장애를 정상 0원 결과로 바꾸지 않는다.

## 6. 조건 검증·개인정보·운영 안전 요구사항

### 계산 근거의 신뢰 경계

- AI가 보낸 `source_type=POLICY_CERTIFICATE`는 출처 **진술**이지 서버의 원문 검증 증명 자체가 아니다.
- 자료 출처, 판독 확인, 지급 조건 검증을 별도 상태로 기록한다. 일반 설계사 키는 서버 검증 상태를 임의로 `verified=true`로 바꿀 수 없다.
- 지급 조건은 출처·적용 상품/가입 시기·검토자·불변 버전을 가진 검토 경로로 승인한다. 약관 수치는 기본 미검증이다.
- V2에서는 검토되지 않은 `rule_config_override`만으로 미검증 규칙을 통과시키지 않는다. 기존 데이터는 삭제하지 않고 미검증 상태로 보존한다.
- 검증 담당자와 절차, 지원 담보 범위를 파일럿 전에 지정한다. 검증된 규칙이 없으면 기능 연결 성공과 계산 가능을 별도로 안내한다.
- AI의 문서 내용, 특약명, 자유문에 들어 있는 지시는 데이터일 뿐이며 권한·규칙·서버 설정 변경 명령으로 해석하지 않는다.

### 저장·동의·철회

- 이름·주민등록번호·증권번호·계좌번호·연락처·문서 원본을 요구하거나 수집하는 필드를 만들지 않는다. 표시 별명·참조값도 비민감 값만 허용하도록 안내·제한한다.
- 구조화 보험·특약·출처 참조도 고객 관련 정보로 취급하고 접근 통제·암호화·수명 정책을 적용한다. 가명 ID를 익명 데이터라고 주장하지 않는다.
- 진료 입력·평가 결과는 DB, 캐시, 로그, 예외 추적, 큐에 저장하지 않는다. 권한 있는 요청 메모리에서 계산하고 응답한다.
- 외부 AI가 처리·보관하는 데이터는 MCP 비저장 정책과 별개다. 설계사 측 AI의 이용 약관·보관·학습 설정·외부 전송 책임을 안내한다.
- 동의/기타 적법한 처리 근거, 목적, 외부 AI 제공, 처리위탁·국외 이전 가능성, 보관·삭제 및 관련 업무 범위는 법률·개인정보 검토 후 확정한다. 체크박스나 MCP 호출만으로 적법성을 보증하지 않는다.
- 처리 권한 철회 시 신규 보험 조회·수정·평가를 차단하고 처리 중단·삭제 절차를 시작한다. 기존 AI 대화/이미 전달된 결과를 원격 삭제할 수 있다고 약속하지 않는다.

### 최소 감사·제한

- 허용 감사 필드: 내부 actor/workspace/client ID, 작업 종류, 시각, 결과 코드, request ID, 접근 권한 변경 내역. 원문 키·해시·PIN·질병코드·진료비·증권번호·입출력 본문은 금지한다.
- 고객 별명·상품명·특약명·예외 문자열도 일반 로그에 넣지 않는다. 사용량 지표에는 고객 ID를 라벨로 넣지 않는다.
- 키는 원문 1회 전달, 서버 해시 저장, 만료·폐기·최소 권한을 지원한다. 비밀은 대화나 도구 인자로 전달하지 않는다.
- actor/workspace별 호출·동시성·페이로드 상한은 여러 Cloud Run 인스턴스에 일관되게 적용한다. 구체적 수치는 파일럿 부하 시험 후 정한다.
- 서비스 운영자에게도 고객 자료 열람을 기본 부여하지 않는다. 비상 접근은 별도 승인·기록 대상이다.

## 7. 출시 게이트와 미결정 사항

다음은 코드 작성만으로 충족됐다고 볼 수 없는 출시 조건이다.

1. SQLite·PostgreSQL에서 고객/업무 공간/하위 객체 격리와 철회 테스트 통과.
2. 동시 재시도·수정·키 폐기·요청 간 identity 누출 방지 검증.
3. 검증된 규칙 범위, 보류 처리, override 우회 방지, 복수 실손 제한 확인.
4. 실제 대상 AI 앱/플랜/버전/설정의 원격 연결 및 보안 자격 전달 확인. 브랜드 이름만으로 호환성을 선언하지 않음.
5. 개인정보 처리·보관 기간·감사 보관 기간·삭제/백업 반영 기한 및 책임 분담 확정.
6. 기존 개인 데이터와 키를 보존하는 이행·복구 리허설 완료.

추가 확정할 항목: 첫 대상 AI 클라이언트와 버전, 헤더 키 연결 가능 여부 및 OAuth 필요성, 검증 담당자, 지원 상품·담보, 호출량 상한, 운영 규모·요금 기준. 정해지지 않은 값은 구현 기본값이나 지원 약속으로 간주하지 않는다.

## 8. 검증 상태

- **사용자 합의:** 외부 AI가 업무 처리, 본 서비스는 설계사·대리점용 MCP에 집중.
- **코드 확인:** 2절의 현재 인증·데이터·평가 및 MCP 구성.

- **인프라 기반 구현:** 별도 V2 서버·DB ownership/migration·키·컨테이너·CI/배포/구축 스크립트. 세부 검증 결과는 STATUS 참조.
