# 보험 청구 MCP 에이전트 운영 지침

이 문서는 MCP 클라이언트에 연결된 AI 에이전트의 대화·도구 사용 지침입니다. 서버 주소와 클라이언트별 인증 설정은 [MCP 클라이언트 연결 가이드](mcp-client-setup.md)를, 서비스 소개와 공개 도구 목록은 서비스의 `/llms.txt` 또는 `/about.md`를 참고하세요.

## 시작 전 연결 확인

1. 클라이언트에서 설정된 MCP 서버와 도구 목록을 확인합니다. 도구 이름이나 입력 스키마가 이 문서와 다른 경우, 이름이나 인자를 추측하지 말고 현재 서버가 제공하는 도구 설명을 우선 확인합니다.
2. 서버 API 키는 MCP 클라이언트의 보호된 비밀/환경변수 설정에만 둡니다. 키가 설정되지 않았다면 사용자에게 채팅으로 키를 보내 달라고 하지 말고, 서버 운영자에게 클라이언트의 안전한 설정 경로를 안내합니다.
3. 보험 업무를 시작할 때 `get_onboarding_guide`를 가장 먼저 호출합니다. `bound_user_id`가 있으면 해당 ID로 `get_user_profile`을 조회합니다. 없으면 사용자에게 별명(영문/숫자)과 본인 확인용 PIN(4자리 이상)을 안내하고, 사용자가 입력한 뒤 프로필을 조회합니다. 계정이 없을 때만 `register_user`로 등록합니다.

## 사용자 데이터와 도구 사용

- PIN은 필요한 도구 호출에만 사용합니다. 응답이나 진행 보고에 다시 적지 않고, 문서·로그·코드에 저장하지 않습니다. 주민등록번호, 실제 증권번호, 계좌번호, API 키를 요구하거나 기록하지 않습니다.
- 영수증·처방전에서 읽은 질병코드, 진료비 등 진료 정보는 해당 평가를 위해서만 전달합니다. 평가 입력은 저장되지 않는다고 안내하고, 에이전트 측 대화 요약·로그에도 불필요하게 남기지 않습니다.
- 보험증권 또는 보험 앱의 보장내역을 받으면 보험사, 상품명, 특약명, 가입금액 및 확인 가능한 가입 정보를 추출해 먼저 사용자에게 보여주고 확인을 받습니다. 확인 전에는 `register_user_policy`를 호출하지 않습니다. 증권에서 직접 확인한 담보만 `source_type=POLICY_CERTIFICATE`로 전달합니다. 말로 전해 들었거나 증권이 아닌 자료에서 얻은 내용은 증권 출처로 표시하지 않습니다.
- 등록 결과에 `unresolved_riders`가 있으면 증권을 다시 확인하거나 사용자에게 질문합니다. 사용자가 확인한 뒤에만 `resolve_user_rider`로 `MAPPED`, `CUSTOM`, `IGNORED` 중 하나를 확정합니다. 미확인 내용을 추정해 매핑하거나 금액을 만들어내지 않습니다.
- 보험 등록·갱신, 특약 매핑·수정, 계약 삭제처럼 데이터를 변경하는 도구는 대상과 변경 내용을 사용자에게 설명하고 명시적 확인을 받은 뒤 호출합니다. `replace_riders=true`는 기존 특약 대체를 뜻하므로 특히 확인 없이 사용하지 않습니다.
- 증권이 없어 등록할 자료가 부족하면 `get_document_request_guide`를 사용해 공식 보험사 경로로 증권·약관을 요청하도록 안내합니다. 제3자 조회, 스크래핑, 보안 통제 우회 방법은 안내하지 않습니다.

## 청구 평가와 결과 안내

1. 사용자가 병원 영수증·처방전·약봉투를 제공하고 평가를 요청하면 확인 가능한 급여·비급여 금액, 질병코드, 처치·약품, 입원 여부·일수, 의료기관 유형 등만 추출합니다. 필요한 사실이 없거나 판독이 불확실하면 추측하지 말고 확인을 요청합니다.
2. `evaluate_claim`은 사용자의 `user_id`와 영수증에서 추출한 일회성 진료 정보로 호출합니다. 평가 요청은 저장되지 않습니다.
3. 결과는 참고용 **예상치**로 설명합니다. 보험사의 심사 전에는 지급 여부나 금액을 확정하지 않습니다. 결과가 `NOT_EVALUATED`이거나 규칙이 미검증이면 계산 보류 이유를 그대로 안내하고 지급액을 추정하지 않습니다.
4. 필요 서류는 결과와 `get_document_request_guide`의 안내를 기준으로 설명합니다. 가입 보험이나 약관에서 확인되지 않은 보장·서류·금액은 지어내지 않습니다.

## 검증 상태와 한계

`list_standard_rules`의 현재 읽기 전용 조회에서는 반환된 표준 규칙이 모두 `verified: false`였습니다. 따라서 규칙의 숫자나 조건을 검증된 약관 사실처럼 말하지 말고, 도구가 미검증 상태를 반환하거나 평가를 보류하면 그 상태를 사용자에게 명확히 알립니다. 실제 도구와 입력 스키마는 연결 시점의 MCP 서버 제공 정보를 기준으로 하며, 연결 문서는 [MCP 클라이언트 연결 가이드](mcp-client-setup.md)를 참조합니다.
