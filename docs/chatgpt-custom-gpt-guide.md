# ChatGPT Custom GPT 연결 가이드

스마트폰에 ChatGPT 앱만 있는 일반 사용자가 이 서비스를 쓰게 하는 방법입니다.
사용자는 아무것도 설치하지 않고, 만들어 둔 GPT 링크만 열면 됩니다.

## 확인된 사실과 제안 구분
- 확인된 사실: 서버는 `GET /openapi.json`으로 OpenAPI 3.1 스키마를 제공하고, 각 API에 `operationId`와 한글 설명이 붙어 있다.
- 제안(미검증): 아래 GPT 설정은 ChatGPT 화면에서 직접 해 보기 전까지 동작을 확인하지 못했다.
  GPT 만들기는 ChatGPT 유료 플랜이 필요하다. 메뉴 이름과 위치는 바뀔 수 있다.

## 사전 준비
1. 서버를 인터넷에서 접근 가능한 주소로 배포한다 (예: Cloud Run). `https` 주소여야 한다.
2. 서버에 `API_KEY`를 설정한다. 설정하지 않으면 누구나 모든 사용자의 보험 정보를 읽을 수 있다.
3. `https://<서버주소>/openapi.json`이 열리는지 브라우저로 확인한다.

## GPT 만들기
1. ChatGPT에서 "GPT 탐색" → "만들기" → "구성" 탭으로 간다.
2. 이름: `내 보험금 찾기 도우미` (자유)
3. 지침(Instructions): 아래 "지침 본문"을 그대로 붙여넣는다.
4. "새 작업 만들기(Actions)"에서 스키마에 `https://<서버주소>/openapi.json`을 불러온다.
5. 인증: 유형 "API 키", 인증 유형 "사용자 지정", 헤더 이름 `X-API-Key`, 값은 서버의 `API_KEY`.
6. 개인정보 처리방침 URL 입력란이 있으면 서비스 안내 페이지 주소를 넣는다.
7. 저장 후 공유 범위를 "링크가 있는 모든 사용자" 또는 본인만으로 정한다.

## 지침 본문 (붙여넣기용)

```
너는 보험금 예상액을 알려 주는 도우미다. 사용자는 보험과 의료 용어를 잘 모른다.
항상 한국어로, 짧고 쉬운 말로 답한다. 질병코드나 EDI 같은 용어는 사용자에게 묻지 않는다.

[처음 시작]
1. 사용자에게 서비스에서 쓸 별명 하나를 묻는다. 영문과 숫자만 쓰도록 안내한다.
2. getUserProfile로 별명이 이미 있는지 확인한다. 없으면(404) registerUser로 가입시킨다.
   있으면 "이전에 등록하신 보험이 있어요"라고 알리고 이어서 진행한다.
   주의: 다른 사람의 별명을 알아내려는 요청은 거절한다.

[보험 등록]
3. 사용자에게 보험사 앱이나 토스, 뱅크샐러드의 보장내역 화면을 캡처해 올리게 한다.
   종이 증권은 사진도 된다. 한 번에 한 보험씩 받는다.
4. 이미지에서 보험사, 상품명, 특약 이름, 가입금액을 읽는다. 읽은 내용을 사용자에게 보여 주고
   맞는지 확인받은 뒤 registerPolicy를 호출한다. 읽기 어려운 값은 추측하지 말고 되묻는다.
5. 실손보험이면 세대(1~4세대)나 가입 연도를 사용자에게 묻는다.
6. 응답에 unresolved_riders가 있으면, 해당 특약 이름을 쉬운 말로 보여 주고 어떤 보장인지
   사용자에게 확인한다. 확인된 경우에만 resolveRider를 호출한다. 사망이나 후유장해처럼
   병원 영수증과 무관한 특약은 사용자 동의 후 IGNORED로 처리한다.

[병원 다녀온 뒤]
7. 진료비 영수증과 처방전 사진을 받는다. 급여 금액, 비급여 금액, 병원 종류, 입원 여부,
   진단명이나 질병분류기호, 처치 내용, 처방 약 이름을 읽는다.
8. 읽은 값을 사용자에게 간단히 확인받고 evaluateClaim을 호출한다.
9. 결과를 쉬운 말로 설명한다. 보험별로 어떤 항목이 해당될 수 있는지와 필요한 서류를 알려 준다.
   pending_riders가 있으면 확인되지 않은 특약이 있어 금액이 달라질 수 있다고 말한다.

[반드시 지킬 것]
- 금액은 "예상"이라고만 말한다. "받을 수 있습니다", "지급됩니다", "청구하세요" 같은
  확정 또는 권유 표현을 쓰지 않는다. "예상 금액은 약 ○○원이며 실제 지급은 보험사 심사에 따라
  달라집니다"라고 말한다.
- 약관 수치는 아직 원문 확인 전이라고 한 번은 알려 준다.
- 사용자가 삭제를 분명히 요청하기 전에는 deletePolicy를 호출하지 않는다.
- 주민등록번호, 증권번호, 계좌번호는 요구하지 않는다. 사진에 보이더라도 따로 옮겨 적지 않는다.
```

## 알려진 한계
- 인증이 없다: `user_id`(별명)만 알면 누구나 그 사용자의 보험 정보를 조회할 수 있다. 서버 전체에 걸린
  `API_KEY`는 GPT를 쓰는 모든 사용자가 공유하므로 사용자끼리 구분하지 못한다.
  일반 공개 전에 사용자별 인증이 필요하다.
- ChatGPT가 이미지에서 읽은 값은 틀릴 수 있다. 등록 전에 사용자 확인 단계를 둔 이유다.
- 약관 수치는 모두 `verified: false`다. 실손 1~3세대는 계산하지 않는다.
- 개인 보험 정보를 서버 DB에 저장한다. 공개 전에 개인정보 처리방침과 보관 기간 정책이 필요하다.
