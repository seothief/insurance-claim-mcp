# 공용 API 키 회전 (운영자 전용)

이 절차는 모든 API/MCP 사용자에게 공유되는 Secret Manager `API_KEY`를 회전합니다. 새 버전을 추가해도 기존 Cloud Run 인스턴스는 시작 시 주입된 이전 값을 계속 사용할 수 있습니다. 새 키로 Cloud Run 리비전을 갱신하면 기존 키를 가진 모든 클라이언트는 설정을 바꿀 때까지 인증에 실패합니다. 따라서 실제 회전에는 별도 승인, 클라이언트 전환 계획, 배포 계획이 필요합니다. 승인 없이 `--apply`를 사용하지 마세요.

## 사전 확인

- Python 3.12 프로젝트 가상환경과 잠금 의존성을 사용합니다.
- 운영자 계정으로 ADC 로그인을 완료하고, 대상 프로젝트의 Secret Manager 조회 및 새 버전 추가 권한을 확인합니다. 서비스 계정 키 JSON은 만들지 않습니다. [gcloud 인증 안내](gcloud-auth.md)를 참고하세요.
- 계획된 변경 시간을 정하고 모든 클라이언트 소유자에게 키 교체 시점을 알립니다. 비밀 키는 공개 문서, 이슈, 소스 코드 또는 일반 채팅에 복사하지 않습니다.

## 실행

저장소 루트에서 현재 상태를 확인합니다. 기본 동작은 **읽기 전용 dry-run**입니다.

```powershell
.\.venv\Scripts\python.exe scripts\rotate_api_key.py
```

활성 버전 수와 번호가 예상과 맞는지 검토합니다. 버전 상태 목록 외에 기존 키 값은 읽거나 출력하지 않습니다. dry-run에 변경이 없는 것을 확인하고 별도의 회전 승인을 받은 뒤 다음 명령을 실행합니다. `--apply`는 대화형이며, 마지막 확인에 `ROTATE`를 입력해야 새 난수 키를 추가합니다.

```powershell
.\.venv\Scripts\python.exe scripts\rotate_api_key.py --apply
```

추가 성공 시 새 키는 터미널에 한 번 표시됩니다. 이를 승인된 비밀 저장소/전달 경로에 즉시 보관하고 클라이언트 소유자에게 안전하게 전달하세요. 키를 셸 인수나 명령 이력에 넣지 마세요. 기존 키를 검색하거나 비활성화하지 않습니다.

그 다음 별도 승인된 배포 절차로 Cloud Run에 새 리비전을 배포해 `API_KEY=API_KEY:latest`를 새 키로 주입합니다. 배포 워크플로는 CI 통과와 `main` 브랜치 또는 수동 실행을 요구합니다. 배포 계획 전에 키 버전을 추가하거나, 클라이언트 준비 전에 새 리비전을 활성화하지 마세요. 기존 값과 새 값의 동시 수용을 지원하지 않으므로 전체 클라이언트 교체 시간대를 조율해야 합니다.

## 확인 및 대응

1. 버전 추가 직후 dry-run으로 활성 버전 상태를 확인합니다. 키 값은 출력되지 않습니다.
2. 승인된 순서대로 새 키를 안전하게 배포하고 Cloud Run 리비전을 갱신합니다.
3. 공개 `/api/health` 및 공개 `/start`를 확인하고, 갱신된 클라이언트에서 인증된 읽기 전용 호출을 검증합니다. 키 없는 보호 API 요청은 계속 거부되어야 합니다.
4. 아직 갱신되지 않은 클라이언트를 확인해 소유자에게 안내합니다. 이전 버전 폐기·비활성화는 별도 영향 평가와 승인 없이는 수행하지 않습니다.
5. 새 키 전달 위치, 버전 번호, 시각, 배포/확인 결과를 접근 통제된 운영 기록에 남깁니다. 키 원문은 기록하지 않습니다.

Secret Manager 상태/권한 오류가 발생하면 도구는 비밀 응답 내용을 숨깁니다. 추측해 재시도하거나 `--apply`를 반복하기 전에 권한과 실제 버전 상태를 별도로 확인하세요.
